# Semantica 采购合规审查 Demo 演示脚本

建议时长：12–15 分钟。面向对象：采购、合规、审计、风控和信息化负责人。

## 一、演示目标

用一条业务故事回答三个问题：

1. 平台能否把分散的采购、供应商、人员、制度和证据连接成可解释的知识图谱？
2. 平台能否识别风险、复用历史先例，并给出可追溯的审查决策？
3. 平台能否持续接收新证据，并治理词表、本体、血缘和数据质量？

## 二、演示前准备

演示前 5 分钟执行：

```bash
cd "/Users/tianqi/Documents/New project 2/semantica"
./demos/procurement-compliance/scripts/reset-and-load-demo.sh
```

看到“验证通过，可以开始演示”后，打开 [http://127.0.0.1:8000/](http://127.0.0.1:8000/)，确认右上角语言为“中”。

请提前记住三个 ID：

- 高风险审查决策：`DEC-2025-042`
- 采购经办人：`EMP-LI-MING`
- 主供应商：`SUP-001`

不要提前导入 `live-blacklist-update.json`。它只用于现场展示增量数据进入图谱。

## 三、业务背景

> 现在我们模拟一笔数据中心服务器采购。申请金额 268 万元，业务部门采用邀请招标，三家供应商已提交报价。传统审查需要在采购系统、供应商主数据、员工申报、工商信息、制度文件和历史审计报告之间来回核对。Semantica 的作用，是把这些对象和证据组织为一个可计算、可解释、可追溯的语义网络。

预期结论：系统发现四类风险，将采购暂缓并升级集团合规委员会复核。

## 四、标准演示流程

### 0:00–1:00｜首页：介绍平台定位

操作：停留在首页。

讲解词：

> Semantica 不是一张静态关系图，而是一个语义智能平台。它把图谱探索、路径分析、规则推理、决策上下文、溯源、时间分析、实体消歧和本体治理放在同一个界面中。今天不按菜单逐项介绍，而是用一笔采购审查把这些能力串起来。

指向左侧六个入口：知识探索、分析、决策、数据增强、治理、本体中心。

本段对应功能：统一工作台、中文/英文切换、模块化工作区。

### 1:00–4:00｜知识探索：从结论进入证据网络

操作：

1. 点击“打开 Semantica 探索器”。
2. 确认顶部显示约 `76 个节点 · 114 条边`。
3. 在搜索框输入 `DEC-2025-042`，点击“搜索”。
4. 点击“服务器采购合规审查决策”节点。
5. 点击“聚焦视图”，让画面只关注该决策的局部邻域。

讲解词：

> 这是系统对本次服务器采购形成的审查决策。点击节点后，平台会高亮它的直接邻居。我们可以看到采购申请、四条制度规则、三类风险信号、四份核心证据、历史决策先例和升级处置对象。这里的每一条线都不是装饰，而是一条带类型、权重、时间和来源属性的业务关系。

> 这次审查命中了四项规则：金额超过 200 万元却使用邀请招标；关联方未申报且未回避；三家投标文件存在围标特征；主供应商的 ISO 27001 认证在评标前已经过期。

操作：在右侧检查器的“目标节点 ID”输入 `EMP-LI-MING`，点击“追踪因果路径”。

讲解词：

> 平台不只告诉我们“高风险”，还可以回答风险结论怎样关联到具体责任人。这里得到的路径是：审查决策 → 采购申请 → 采购经办人李明。路径查找可以用于利益冲突穿透、供应链影响分析和审计取证。

可选操作：点击“语义距离”，展示预置向量发现的相似对象；点击“时序”查看 2019–2025 的时间范围和证书失效窗口。

本段对应功能：全文检索、完整图谱、聚焦邻域、路径查找、结构/语义距离、时间语义、节点属性检查。

### 4:00–6:00｜决策智能：解释为什么暂缓采购

操作：点击左侧“决策”，再选择 `DEC-2025-042`。

讲解词：

> 决策工作区把知识图谱转换成可审阅的决策档案。左侧同时保留三个案例：本次高风险采购、一个合规通过的办公家具采购，以及 2024 年被驳回的同类服务器采购。

> 当前决策的结果是“暂缓采购并升级合规复核”，置信度 0.96，风险评分 92。下方因果链列出了采购申请、违反的政策、支撑证据、风险信号、处置对象和历史先例。审查人员可以从结论逐层回到原始证据，而不是只接收一个黑盒分数。

指向：

- `POL-OPEN-TENDER`：采购方式与金额阈值；
- `POL-RELATED-PARTY`：关联方回避；
- `POL-ANTI-COLLUSION`：围标串标；
- `POL-SUPPLIER-QUAL`：供应商资质有效性；
- `DEC-2024-088`：同类历史先例。

操作：快速点击 `DEC-2025-017`。

讲解词：

> 同一套模型也会保留“为什么通过”的正向案例。办公家具采购采用公开招标，关联方筛查无命中，审批和比价记录完整，因此结论为通过。这样能避免平台只会报风险、无法解释正常业务。

本段对应功能：决策档案、因果链、历史先例、合规与非合规对照、置信度和上下文保留。

### 6:00–8:00｜规则推理：把企业制度变成可执行规则

操作：点击左侧“分析”→“推理实验台”。将“事实”替换为：

```text
high_value(PR-2025-042, true)
related_party(SUP-001, EMP-LI-MING)
shared_ip(BID-HUACHEN, BID-XINHAI)
certificate_expired(SUP-001, true)
```

将“规则”替换为：

```text
IF high_value(?request, true) AND related_party(?supplier, ?buyer) THEN requires_escalation(?request, ORG-COMPLIANCE)
IF shared_ip(?bid1, ?bid2) AND certificate_expired(?supplier, true) THEN flags_supplier(PR-2025-042, ?supplier)
```

保留“将推导事实写入图谱”勾选，点击“运行推理”。

预期结果：

```text
requires_escalation(PR-2025-042, ORG-COMPLIANCE)
flags_supplier(PR-2025-042, SUP-001)
```

讲解词：

> 这里演示的是确定性、可审计的前向链推理。事实来自业务数据，规则来自企业制度，输出明确说明哪条规则被触发。勾选写入图谱后，推导结果会成为带有 `inferred` 标记的新关系，并进入本次会话的审计日志。这个演示不依赖大语言模型，因此结果可重复。

本段对应功能：事实/规则建模、前向链推理、推导关系写回、可重复的合规规则执行。

### 8:00–10:00｜实时更新：新监管证据进入图谱

操作：

1. 点击左侧“数据增强”→“导入与导出”。
2. 选择文件：

```text
/Users/tianqi/Documents/New project 2/semantica/demos/procurement-compliance/data/live-blacklist-update.json
```

3. 点击“上传到图谱”。
4. 确认提示“已导入 1 个节点 · 1 条边”。
5. 切换到“注册表”。

讲解词：

> 现在模拟审查过程中收到一条外部监管通报：华辰数字科技在其他项目中也出现投标文件异常一致。平台以增量方式加入一个监管通报节点，并把它连接到供应商 `SUP-001`。不需要重建整个知识库，新增证据会立即进入图谱和审计日志。

> 注册表记录了刚才的推理和导入操作，帮助回答谁在什么时间以什么方式改变了知识图谱。

本段对应功能：JSON/CSV 导入、增量更新、审计日志、图谱热更新、快照导出。

### 10:00–11:30｜实体消歧：识别供应商主数据重复

操作：点击“实体消歧”，确认阈值为 `0.90`，点击“运行重复项扫描”。

预期：只出现一组候选：`SUP-001` 与 `SUP-001-ALT`，相似度约 0.90、置信度约 0.95。

讲解词：

> 采购系统和历史供应商主数据常出现同一主体多条记录。平台在高置信阈值下识别出两个华辰供应商节点；两条记录的统一社会信用代码相同，但来源系统和名称字段不同。系统把它标成候选，而不是直接删除，仍由数据治理人员确认。

可选操作：进入“差异与合并”，主节点填 `SUP-001`，重复节点填 `SUP-001-ALT`，只展示字段差异，不点击最终合并。若点击合并，演示后运行重置脚本即可恢复。

本段对应功能：相似度去重、候选解释、人工确认、实体合并。

### 11:30–13:00｜血缘治理：从决策回到数据来源

操作：点击左侧“治理”→“PROV-O 血缘”，输入 `DEC-2025-042`，点击“追踪”。

讲解词：

> 对合规和审计来说，结论必须能回到证据和产生证据的活动。PROV-O 血缘视图按照 W3C 的 Entity、Activity、Agent 语义组织决策周边信息。我们可以看到决策依赖采购申请、投标分析、关联方报告和资质证书，并由合规委员会负责处置。

操作：点击“导出 Markdown”。

讲解词：

> 这份血缘报告可以作为审查底稿的一部分导出，也可以通过 JSON 接入其他审计系统。

随后点击“知识图谱概览”和“本体摘要”，各停留数秒。

本段对应功能：PROV-O 血缘、证据链、治理概览、Markdown/JSON 报告。

### 13:00–14:30｜词表与本体：让业务口径可以治理

操作一：点击“知识探索”→“词表浏览器”。

讲解词：

> 知识图谱不是把字符串随意连起来。SKOS 词表统一了三组业务口径：合规风险、采购方式和审查结论。比如“围标”“陪标”可以作为同一概念的首选标签和别名，供不同系统映射。

展开并指向：

- 合规风险：围标串标、未披露关联交易、供应商黑名单、资质失效；
- 采购方式：公开招标、邀请招标、单一来源；
- 审查结论：通过、暂缓升级、驳回重采。

操作二：点击左侧“本体中心”。

讲解词：

> OWL 本体进一步定义领域结构：采购申请、投标、供应商、员工、政策、证据、风险信号和审查决策是什么，以及它们能通过什么关系连接。注册表中可以看到采购合规本体和术语表，还可以继续进行版本、对齐、健康度和 SHACL 约束治理。

本段对应功能：SKOS 词表、层级概念、OWL 本体注册、本体版本/对齐/健康度/SHACL 治理。

### 14:30–15:00｜总结

讲解词：

> 回到最初的问题：Semantica 把一笔采购从“系统给出 92 分高风险”，提升为“结论—规则—证据—人员—供应商—历史先例”全部可追溯的语义网络。它既能执行确定性规则，也能发现语义相似对象；既能接收实时证据，也能治理数据质量、词表、本体和血缘。生产落地时，我们只需要把演示数据替换为 ERP、SRM、供应商主数据、员工申报和外部监管源，并接入企业权限与持久化存储。

## 六、常见提问答法

“这是固定画出来的图吗？”

> 不是。所有节点和关系来自 JSON、RDF/TTL 或 API 导入；路径、邻域、时间快照、推理和去重均由平台实时计算。本 Demo 还保留了现场增量文件，用于证明图谱可以动态更新。

“决策是大模型生成的吗？”

> 本次规则演示使用确定性的 IF/THEN 前向链推理，不依赖大模型。Semantica 也可以与语义抽取、向量相似度和外部模型组合，但合规结论可以保留为可重复、可审计的规则路径。

“能接哪些企业系统？”

> Demo 使用标准 JSON、CSV、SKOS 和 OWL。生产中可通过接口或数据管道接 ERP、SRM、主数据、员工申报、合同、工商和监管数据。具体连接器需要结合企业系统确定。

“是否支持权限和持久化？”

> 当前本地演示为回环地址上的匿名单机环境，Explorer 图谱状态在内存中，便于一键重置。生产环境应启用 API Key/统一身份认证、持久化图存储、备份、细粒度授权和审计留存。

“为什么还需要本体和词表？”

> 规则和图谱要跨系统长期复用，必须先统一“供应商”“关联方”“围标”“审查结论”等概念及其关系。本体负责结构约束，词表负责业务口径和同义词，两者让数据接入和规则执行不依赖某一个系统的字段命名。
