# 第三步：追加供应商黑名单风险证据

本步骤学习如何把一条外部风险数据增量加入现有图谱，并沿已有业务关系追溯到风险证据。

## 前置条件

必须已经上传第一步和第二步文件。知识探索页面应显示：

```text
7 个节点 · 7 条边
```

并且能够搜索到：

```text
SUPPLIER-001
```

## 要上传的文件

`3-供应商黑名单风险证据.json`

该文件只新增：

- 1 个监管通报节点：`NOTICE-001`
- 1 条供应商到风险证据的关系：`hasRiskEvidence`

它不会重复导入供应商，而是通过 `SUPPLIER-001` 引用第二步已经存在的华星科技有限公司。

## 页面操作

1. 打开“数据增强”。
2. 进入“导入与导出”。
3. 选择 `3-供应商黑名单风险证据.json`。
4. 点击“上传到图谱”。
5. 页面应提示“已导入 1 个节点 · 1 条边”。
6. 回到“知识探索 → Semantica Explorer”。
7. 点击“重新加载图谱数据”。
8. 页面应显示“8 个节点 · 8 条边”。

## 查看新增证据

搜索：

```text
NOTICE-001
```

点击节点后，应该看到：

```text
采购诚信平台通报：华星科技有限公司列入采购观察名单
```

主要属性包括：

- 通报编号：`BLACKLIST-2026-017`
- 风险类别：供应商黑名单
- 严重程度：高
- 数据来源：采购诚信信息平台
- 状态：有效

## 追踪完整证据链

1. 搜索并选中 `DECISION-001`。
2. 在“目标节点 ID”输入：

```text
NOTICE-001
```

3. 点击“追踪因果路径”。

预期路径：

```text
DECISION-001
→ CASE-001
→ BID-001
→ SUPPLIER-001
→ NOTICE-001
```

业务解释：

```text
审查结论
→ 审查采购申请
→ 采购申请收到投标文件
→ 投标文件由华星科技提交
→ 华星科技关联外部黑名单通报
```

## 这一步能证明什么

这一步证明平台能够把后来到达的外部风险证据，接到原有采购业务链上，并返回一条可追溯的证据路径。

这一步还没有自动执行合规规则，也不会自动修改 `DECISION-001` 的审查结论。下一步才会把这条证据转换成明确的风险信号和审查规则结果。

## 与正式本体的关系

`regulatory_notice` 对应正式本体中的 `pc:RegulatoryNotice`。

本步骤使用的 `hasRiskEvidence` 是为了让有向路径能够从供应商继续走到证据节点，目前尚未在正式本体中定义。正式化时应在本体中补充：

```text
hasRiskEvidence
domain: Supplier
range: RegulatoryNotice
```

这也是后续“实例数据映射到正式本体”时需要处理的一项内容。
