# 第六步：配置并运行实例约束检查

第五步定义了“有哪些类和关系”，第六步定义“具体数据必须满足什么要求”。

例如：

```text
本体定义：PurchaseRequest 是采购申请类
SHACL 约束：每个采购申请必须填写金额和采购方式
```

## 要使用的文件

`6-采购合规实例约束.ttl`

这个文件不上传到普通数据导入页面。它的内容要复制到 SHACL 工作室的编辑器中。

## 页面操作

1. 打开左侧“本体中心”。
2. 进入“SHACL”。
3. 在右上角本体下拉框选择“采购合规审查本体”。
4. 打开 `6-采购合规实例约束.ttl`，复制全部内容。
5. 用复制内容替换中间 Turtle 编辑器中的原内容。
6. 点击“验证”。

不要先点击“生成严格约束”。本步骤使用的是我们针对当前 JSON 实例类型编写的约束。

## 预期结果

当前 1～4 步数据完整时，验证结果应为：

```text
conforms
0 violations
```

含义是：当前实例数据通过了这批结构和取值检查。

## 检查了哪些内容

### 审查结论

- 必须通过 `reviews` 关联采购申请；
- 如果存在 `flags_supplier`，目标必须是供应商。

### 采购申请

- 必须填写 `amount_cny`；
- `procurement_method` 必须是公开招标、邀请招标或单一来源；
- 必须关联至少一份投标文件；
- 必须关联经办人。

### 投标文件

- 必须关联提交投标的供应商。

### 供应商和监管通报

- 供应商必须有供应商编号；
- 风险证据关系必须指向监管通报；
- 通报严重程度必须是低、中或高；
- 通报状态必须是有效或失效。

### 材料和制度

- 采购材料必须关联来源采购申请；
- 制度必须有金额阈值和要求的采购方式。

## 这一步会不会修改图谱

不会。SHACL 验证是只读检查：

```text
图谱实例 + SHACL 约束 → 验证报告
```

它不会新增节点、关系，也不会自动修复数据。

下一步可以故意上传一条不合格数据，再运行同一份约束，观察平台如何定位具体错误节点。
