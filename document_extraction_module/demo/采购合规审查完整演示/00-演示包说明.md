# Semantica 采购合规审查完整演示包

这套材料用于演示已经部署的 Semantica Pro 文档抽取功能。业务故事是一家制造集团采购智能仓储系统，系统需要同时检查采购过程、供应商风险和合同关键条款。

## 推荐演示方式

- 正式地址：`http://121.196.149.55:9009/`
- 使用管理员提供的网关账号登录，不要把账号或模型密钥写入演示材料。
- 主演示先使用“规则抽取”。它不调用大模型，速度快、结果可复现，适合现场稳定演示多文件、多模板、进度、预览、筛选和导出。
- 如果要演示语义理解，再单独上传 `3-采购合同关键条款确认稿.txt`，只选择“合同关键要素”，切换到 Kimi K3。这样只产生一个模型任务，耗时和费用可控。

## 这套演示真实展示什么

1. 三份文档可以一次上传。
2. 三个场景模板可以同时选择。
3. 后端会执行 3 份文档 × 3 个模板，共 9 个独立子任务。
4. 每个模板分别抽取，最后合并去重；不是把三套定义拼成一个提示词。
5. 实体和关系保留来源模板、文件、证据文本和模板版本。
6. 结果可以按模板过滤，也可以下载 JSON 或 CSV。

## 必须如实说明的边界

- 规则模式只匹配模板中已经配置的正则表达式，不会理解没写入规则的自然语言。
- 当前“合同关键要素”模板的规则模式配置了实体规则，但没有配置关系正则，所以规则模式能抽到合同主体、金额、日期和条款，不会自动生成合同关系边。
- Kimi 模式可以根据类型说明理解上下文并生成候选关系，但结果仍需要结合原文证据人工核对。
- 文档抽取结果是候选知识，下载后由用户确认再导入图谱；当前版本不会自动写入 FalkorDB。

## 离线复核

在仓库根目录运行：

```bash
python "document_extraction_module/demo/采购合规审查完整演示/30-验证工具/1-生成规则模式演示结果.py"
```

脚本会严格调用当前源码中的 `DocumentExtractionService`、三个内置模板、结果合并器和导出器，重新生成 `40-实际输出` 下的 JSON 与 CSV，并在终端打印统计摘要。
