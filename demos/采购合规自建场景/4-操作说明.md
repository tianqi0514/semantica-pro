# 第四步：用规则推导供应商风险关系

本步骤第一次使用平台的推理实验台。目标是根据三条标准化事实和一条规则，推导出：

```text
flags_supplier(DECISION-001, SUPPLIER-001)
```

通俗含义是：当前审查决策应当标记华星科技有限公司。

## 前置条件

必须已经完成第三步。当前图谱应显示：

```text
8 个节点 · 8 条边
```

并能查到从 `DECISION-001` 到 `NOTICE-001` 的路径。

## 输入文件

本步骤不上传文件，而是将下面两个文件的内容复制到推理实验台：

- `4-推理事实.txt`
- `4-推理规则.txt`

## 第一次运行：只预览，不写图谱

1. 打开左侧“分析”。
2. 进入“推理实验台”。
3. 将 `4-推理事实.txt` 的三行内容复制到“事实”输入框。
4. 将 `4-推理规则.txt` 的一行内容复制到“规则”输入框。
5. 关闭“将推导事实写入图谱”开关。该开关页面默认可能是开启的，请先确认关闭。
6. 点击“运行推理”。

预期输出：

```text
flags_supplier(DECISION-001, SUPPLIER-001)
```

同时应该显示：

```text
1 条推导事实
0 条新增关系
仅预览
```

此时图谱仍然是 8 个节点、8 条边。

## 输入是怎样匹配的

三条事实分别表示：

```text
当前决策涉及华星科技
华星科技存在 NOTICE-001 风险证据
NOTICE-001 的严重程度为高
```

规则中的变量会得到这些值：

```text
?decision = DECISION-001
?supplier = SUPPLIER-001
?notice   = NOTICE-001
```

将变量代入规则结论后得到：

```text
flags_supplier(DECISION-001, SUPPLIER-001)
```

## 第二次运行：写回图谱

确认预览结果正确后：

1. 打开“将推导事实写入图谱”开关。
2. 再点击一次“运行推理”。
3. 预期显示“新增 1 条关系”和“图谱已更新”。
4. 回到“知识探索”，点击“重新加载图谱数据”。
5. 图谱应显示：

```text
8 个节点 · 9 条边
```

新增关系是：

```text
DECISION-001 --flags_supplier--> SUPPLIER-001
```

这条边的属性会记录：

```text
inferred = true
inferred_from = flags_supplier(DECISION-001, SUPPLIER-001)
reasoning_mode = forward
rules = 本次提交的规则
```

## 重要限制

事实输入目前需要手工填写。推理实验台不会自动读取图谱中的 `severity=高`，也不会自动把刚才查到的路径转换成 `decision_involves_supplier(...)`。

因此本步骤证明的是：

```text
标准化事实 + 确定性规则 → 可预览的推导结果 → 可选写回图谱
```

它还没有实现：

```text
原始图谱属性 → 自动生成规则事实
```

生产系统需要在推理引擎前增加“事实生成层”。

## 避免重复写入

写回模式只运行一次。当前后端不会检查同一条推导边是否已经存在，多次点击会写入重复关系。
